候选在 `ProgressFinding.finding_id` 的参数说明中明确：新增发现省略 ID；更新时原样复制本任务当前已有 ID。参数类型、默认值、生成算法、校验、证据权限和执行逻辑保持现有合同。

## 零模型资格

在已安装项目依赖的 Python 3.14 环境，从仓库根目录执行：

```sh
python -B backend/scripts/check_harness_h1.py --output /tmp/researchloop-h1-check
```

输出目录必须尚不存在。入口使用显式配置、独立临时 SQLite、合成 PDF 与替身决策，覆盖应用启动和内部默认配置接点，并限制文件写入和网络访问。它复用阶段进展与交接回归，再通过后端 HTTP 提交、原生 Worker 执行、任务结果与事件读回核对业务链路。具体运行数量和未执行项以生成的结果为准。

HTTP 的 `POST /api/tasks` 返回 202 表示排队；Worker 完成后再从 `GET /api/tasks/{task_id}`、`/events` 或 `/stream` 读取终态。前端输入不是 Agent 验证的必要步骤。

替身的回答、请求数、usage 和耗时不代表真实模型效果。当前真实模型预算为 0；真实效率比较还需固定相同材料、历史、权限、验收要求及独立预算。
