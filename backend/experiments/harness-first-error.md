# 实验首错停止与阶段交接离线回放

本轮业务基线为既有Supervisor范围优化版。共同入口起点为`db67d14`，其业务源码与`e85fa87`一致。Supervisor所有提示词保持不变，包括第1、4、7条；本轮只修实验控制层，业务交接改动另行审核。

## 持久停止合同

- `first_error_policy_version=1`进入账本不可变配置。旧合同不自动迁移或恢复，历史真实账本只作只读审计。
- 预算、时钟和重复启动拒绝在SQLite写事务内保存`first_error`及兼容的`halt_reason`，事务提交后再抛出异常，避免停止记录随异常回滚。
- 首错记录包含具体原因、操作、根身份、预留身份、检测时间、当时批/根占用、候选预留及上限。后续拒绝、未知收据和清理不覆盖首错。
- 以`mark_sent`作为发送放行线性化点，它与首错共用数据库写锁。首错后不能新增预留、根任务或发送放行；首错前已放行请求仍保守结算，未知结果保留完整预留。尚未放行的请求可转为`not_sent`释放占用，整批仍冻结。
- 源码身份、provider模型/入口、请求/视觉合同及请求日志错误均接入同一停止门；格结束读取持久首错，阻止进入下一格或语义审核门。
- `mark_sent`提交至底层HTTP函数进入之间可能发生调度。此前已放行请求属于在途，不声称首错后物理socket绝无发送，也不通过串行化整个HTTP响应改变并行语义。

额度、费率、请求上界、业务预算与既有语义审核门均保持原合同。此修复须同时应用于未来A/B两侧，不作为业务效率收益。

## 零模型验证

`test_harness_ab_first_error.py`使用独立SQLite、真实线程/进程锁和内存HTTP，覆盖拒绝后余额回落仍冻结、首错唯一、跨进程可见、未放行释放、已放行结算、身份门及发送边界。既有预算/传输/双层收据测试继续保护计费、视觉、压缩流和未知占用。

`replay_research_handoff.py`只读显式指定的历史SQLite，在新私有副本上运行真实工具与`execute_tools`单节点；网络及模型调用被禁止。它比较原参数、仅省略新建ID、窄错误分类的离线反事实与重复失败停止。原始发现仍是`unreviewed`；通过不代表模型会自动改正、科学结论正确、Worker完整恢复或时延/Token改善。真实材料、参数、ID、数据库及结果均保存在私有目录，通用脚本不附带这些输入。

## 下一项业务候选（尚未实施）

未知新建发现ID目前被包装为可重试`execution_error`，交接状态机的有界参数反馈只接收`validation_error`等窄类型。建议后续仅为未知发现ID定义稳定的窄异常类型，在研究工具处理器中映射至现有参数纠正通道，复用一次反馈槽。其他执行错误、证据权限、旧版本、跨任务/未知ID拒绝、重复失败及停止上限保持严格。禁止静默删除未知ID后自动当新建，也不扩写Supervisor职责。

上述业务候选只给审核方案，不改变`backend/research_loop`。真实A/B须另行冻结新样本、预算及授权；本轮离线工作不授予模型调用、合并或部署权限。
