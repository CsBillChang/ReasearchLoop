# 固定输入的CPU重排参数对照

本入口只用于独立组件实验，复用已冻结的完整候选、原始问题与正文，不接入默认API/Worker或业务配置。只比较CPU intra_op线程2与4；inter_op=1、同权重/tokenizer/运行时、batch4、原顺序、512拒绝边界保持。

## 执行合同

显式提供冻结文件、独立期望SHA和全新空输出目录。冻结固定cases/feed/执行格、模型文件/源码/包身份、授权和预算。先运行prepare-only，在不加载ORT/模型的条件下检查合同；真实运行前再次校验，两个配置显式加载并检查CPU provider与模型输入名。

每次底层session.run前核实际int64张量shape、little-endian字节hash及批次顺序与准备投影一致。主reranker_wall_seconds包含同样的feed核对、分词、padding、评分/输出校验与最终排序；另记录feed_verification_seconds/native_session_run_seconds，不能相减包装更快的净耗时。模型加载、候选准备、读/hash/写文件在热计时外。

114题、每组3热轮加1初始化，最多686次score调用、16134个query-passage对、预计4050次底层Session.run、60分钟。按冻结计划串行轮换先后，不重试、不自动扩网格或覆盖输出。输入/权限/资源/预算错误立即停，失败与未执行格保留。

两个配置均使用既有CPU模型；无生成/外部API/Embedding、依赖或权重下载、新索引、Apple后端或部署更改。进程内守卫拒绝网络、数据库、子进程和输出外写入，但不替代OS沙箱；显式关闭共享pycache写入。

## 报告和采用

只比较同期同边界的重排墙钟，不能与历史包含候选选择的完整链路时间相减。每题三轮中位数后报P50/P95、配对变化、n/N与共享机负载条件；不把三轮当三个独立问题。质量保持原可回答题分母/非穷尽标签，报Recall@5/@8/@10、MRR@24、候选覆盖、逐项分数/排名变化、三轮稳定性，以及相对历史2线程的漂移。

失败/空结果保留零分，未执行/unknown保持N/A且完整汇总标不完整。公平时延仅用双方三轮都成功的共同题目，公开排除量。指标不下降且有实际时延收益才交审采用，未合并前默认业务不变化。CPU结果后再考虑单独Apple后端，完成后收束该阶段优化。

公开代码在隔离实验分支保存到GitHub；私有输入/标签/原文/模型/记录不上传。撤销使用git revert对应实现提交，不强推、不reset部署目录；环境通过不写入与前后核对保护，Git不代表环境回滚。
