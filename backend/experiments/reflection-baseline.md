# Reflection 当前基线评测准备

本实验测量已有稿件经过当前普通回答核验、模型局部修订与持久交付后的质量及增量成本。当前阶段提供离线准备和显式替身资格，不包含业务优化或部署切换。

## 固定设计

分为六稿链路试点、四十稿受控基线、八份历史自然回答回放。三批分别统计，原稿不处理为零新增调用的对照。每稿仅一次试验，失败和未创建项保留；不按成功结果挑题或重新试验。

正式集五类各八稿：全部正确、事实或数字错误、必要条件遗漏、推断或引用不充分、证据不足。每稿三个预先冻结的语义检查点，共八十八个原正确点、二十四个可修正问题、八个缺证问题。至少二十篇既有论文，每篇最多两稿；构造集与自然集不合并成生产错误率。

输入只投递显式 `model_input`，标签和出处审阅记录留在独立文件。材料标签须人工确认，旧 Reviewer 判断、后续更正和参考修订不能进入新的 Reviewer 上下文。

## 文件入口

- `scripts/prepare_reflection_baseline.py`：只提供 `validate/freeze`，校验显式清单、字节 hash、输入标签隔离和初始页范围。通过结构校验不会生成真实调用授权。
- `scripts/reflection_baseline_runtime.py`：显式隔离 SQLite、目录与模拟供应商的链路资格；真实供应商模式尚未开放。
- `tests/unit/test_prepare_reflection_baseline.py` 与 `tests/integration/test_reflection_baseline_runtime.py`：合成输入的身份、持久交付、恢复、失败和预算边界验证。

评测真实模型入口需另行完成材料审核、实际配置/费率冻结和发送前额度预留资格。不得为本实验修改通用组件 CLI 的真实发送拒绝门。

## 评分与计量

最终交付正文是主评分对象；轨迹用于区分未识别、判断错误、修订错误、修订拒绝和交付未落实。纠错、条件补全与推断修正分开报告；正确内容的误改和删除损失分别记录。新增主张须额外审阅，不扩大原问题的分母。

模型请求按根及全部子任务的物理收据计量，保留失败、unknown 和缺 usage。缓存输入是输入子集、推理输出是输出子集，不能重复相加。结构测试成绩不作为真实质量或节省成本的证据。

## 隔离与回退

专用 Git 分支保存评测前源码检查点和准备器实现提交；私有论文、标签、历史回答、运行参数、数据库与凭据留在本机，不提交到 GitHub。当前部署目录、默认分支、业务配置与日常进程不切换。

运行目录、SQLite、输出目录与依赖缓存显式指向新的实验目录。替身资格禁止任何真实 socket 连接，不加载部署 `.env`，不启动 HTTP/Worker 服务、MySQL 或向量服务。不能仅因使用工作树就宣称完成资源隔离。

需要撤销实验代码时，对专用分支的实现提交执行 `git revert <implementation-commit>`；若仅需查看评测前版本，另建工作树检出记录的 baseline commit。不要对部署目录执行 reset、不要强推，也不要把私有实验数据的回退和 Git 代码回退混为一谈。
