## 四、固定的数据输入输出

### 1. 阶段研究进展（已实现工程接线，不是长期用户偏好）

最低字段：`task_id / goal_id / revision`、当前子目标、发现及稳定 finding ID、原文引用（document/version 或 content hash、evidence ID、可用时的页码/字符区间）、已读范围、未解决问题、下一步需求、产生它的 action 身份、核验状态。这里的“发现”由执行任务的模型在研究过程中提交；代码只验证来源身份/权限/位置及合并规则，不从模型内部推理日志猜测事实。

- 已读范围由成功工具观察生成；有 evidence 不自动产生 findings。
- 新发现默认为未独立核验；有引用不自动标成 supported。后续审校按当前发现版本绑定，旧判断不自动覆盖新版本。
- 最小实现采用一个阶段进展动作 `record_research_progress`，允许在当前决策返回中与其他工具一起调用，无需为每次读页额外发一次模型请求。它不结束任务、不写笔记文件。`finish_research` 复用同一校验/合并入口再封存结果，避免两套数据合同。
- 复用现有 action 的持久写入和 Checkpoint 机制：成功进展 action 是可重放来源，Checkpoint 只是投影缓存；写入/恢复按 task、action ID 和修订版本幂等。先写成功 action，再对后续决策可见。快照落后时重放，不丢进展或复制结论。
- 第一版不新建第二套会话或向量记忆库，不改既有表。如果现有 action 事务无法满足上述原子性，先明确缺口并更新本合同，再决定是否需要追加迁移，不能边实现边扩表。
- `save_policy=deny` 继续禁止 Markdown 保存；内部任务进展持久化与导出笔记是不同操作。

### 2. 单次角色上下文（已实现定向修复）

输入为当前用户指令/澄清、角色权限、目标覆盖、阶段发现、未解决问题、有效材料版本、当前所需原文窗口、最近完整工具往返。输出为待发 messages、实际工具 schemas、可读回档案指针与容量诊断。

固定规则：先保留当前指令、权限和任务进展；按当前问题选择足够解释含义的连续原文窗口；旧详细观察整组归档，重复元数据只出现一次。原始 receipt/messages 不改写。压缩不能拆散未完成的 tool call 与 response；来源身份与文字一起保留，不能只留下裸 ID 或恰好命中的几个词。

Supervisor 与 Researcher 共用投影原则，仍保持独立上下文和权限；不把父会话全部复制给子任务。需要旧证据时用该角色实际可用的读取工具，权限/版本继续校验。系统自己裁掉了所需文字时，读回是上下文恢复，不算没有进展的科研重试。

容量计量分别记录字节、估计 token、供应商实际 usage，不混用名称。可验证的 tokenizer 优先；没有与供应商一致的 tokenizer 时，用已保存请求/usage 对覆盖中文、英文、JSON/工具场景的估计方法做校准和保守余量验证，明确误差，不声称精确计量。模型窗口、最大输出与 schemas 开销都保留检查；不通过粗暴除常数或关掉所有检查来获得通过。

### 3. 取证进展与结束（已实现观察分类与本地精确读取复用）

输入是目标、问题、来源版本/实际读取范围、查询及返回内容指纹、前后发现/缺口。输出是可解释的观察：新增有效证据、发现更新、确认冲突、上下文读回、相同结果无新增、参数失败/外部失败；供 Supervisor/Researcher 决策。

- 同一页用于回答新问题、有新的结论或补足被裁掉的必要上下文，可以有进展；不按“见过 evidence ID”一律禁止。
- 换 query 但材料/发现/缺口不变，不算新增证据；新增不同 ID 却相同内容也不算。
- 相同版本/范围的纯只读动作可复用已成功结果，但下一次模型确实要看见需要的文字，不能只返回“已读过”。不会因缓存命中直接批准答案。
- 参数错误、引用位置错误、权限拒绝不算事实反证；缺证仅表述已查范围，不能说整篇/全世界不存在。
- 模型根据观察选择补读、调整范围、汇合或明确结束；代码阻止同状态无理由的重复昂贵操作时，返回可理解原因与可行动选项，不暗中换论文、生成结论或把 partial 改 completed。
- 在确无新材料/策略可执行或遭遇真实外部失败时合理停止；记录已完成、未完成及原因。资源不足和内部错误单独标识，不能都叫“论文缺证”。

## 七、怎样算修完

三个必需场景加兼容检查，固定范围通过即可停止，不追求所有论文永远成功。

| 场景 | 必须观察到的结果 | 不能冒充通过 |
|---|---|---|
| 正常比较 | 原两 PDF/原问题，实际读取→合理委派→双方非空发现→围绕原维度比较→聊天交付；引用归属/关键方法/限定与原文一致，未作跨任务排名；符合原篇幅及禁止保存要求 | 只有单篇成果、内部容量失败后 partial、把模型未经核验断言视为事实 |
| 压缩后追问 | 同会话实际触发压缩，最新问题/用户约束/材料版本/阶段成果仍可读；按问题补读或复用，有完整答复 | 仅测试压缩函数、仅保留 ID、重新全文精读来掩盖接续丢失、继承旧保存许可 |
| 合理失败 | 受控材料不可读或已有明确缺证时，保留实际已完成发现、已查范围、未完成项和真实原因，任务进入可读终态 | 将内部上下文/交接缺陷报告为外部论文缺证；伪造发现或用无依据全篇否定收尾 |
| 兼容与恢复 | 单元/隔离用例通过；旧成功 receipt 无重发，unknown 保守处理，取消/lease/权限/文件保护有效；无论文 ID/固定页码分支 | 用替身通过代替真实语义验证，或因为测试数量增加而忽略原失败任务 |

先完成零模型和隔离门，再讨论真实复验。真实复验前给用户可读的代码版本、完整问题、材料/来源 hash、实际配置和预估代价；**本次不预设新的请求数/Token/时长上限，不沿用旧 20/48/4 等开发批次参数作为产品要求。** 用户接受的运行范围或明确的“不设累计预算”要求才是下一次执行依据，数据库实际配置需读回一致。供应商物理上下文/输出上限、取消、权限和 unknown 保护不是任意实验配额。

一次固定范围产生终态后报告成功或失败；不能因仍有额度追加实验、换论文或新增 protocol。参数/容量/交接错误只修对应工程缺口；新语义错误先分类，不自动扩建审校系统。第二份独立材料组合或更大规模是后续采样事项，不用新样本不断延长本修复。

**收束输出：** 修复文件清单、零模型重放、隔离结果、真实比较与压缩追问（若获授权）、受控失败、原始失败保留、实际用量、文件/数据库保护、局限。若三场景和兼容门满足，核心修复完成，可以开始第二项 Reflection 范围讨论；部署读回和发布另行执行，不把测试完成当已上线。
