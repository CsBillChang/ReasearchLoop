# 评测、语料与模拟使用边界

## 已有真实结果

固定6份PDF、63页、282片段、24题：21题有事前相关片段标注、3题缺证。标签为开发Agent选定并对照原文的片段，非独立双人或穷举金标准。质量指标按有答案题计算，耗时为本机热查询组件计时，不是完整问答时间。

|---|---:|---:|---:|
| BM25 | 66.67% | 0.3127 | 1.22 |

2026-10-11排名/推理候选：MRR 0.3767→0.5112，重复测量中位耗时2233.84→1033.32ms，但Recall 90.48%→85.71%，未采用。2026-10-12效率候选：Recall不变，MRR 0.3767→0.3658，耗时1969.92→1231.85ms，未采用。两批与原单次基线不能混算。

公开汇总不含原文全文和私人轨迹；原始材料/receipt/排名留在本机artifacts。仓库携带评测脚本和固定问题，不因没有公开私人材料就宣称读者可直接重跑旧真实模型账本。

## 语料规模与RAG是否必要

评测集大小不等于产品索引总量，也不是系统容量上限。这里不报告未经当前数据库盘点核实的全库论文数。RAG的使用目标是对已授权材料进行局部证据定位、跨材料比较和重复查询；少量材料直接读全文可能更合理。不能为展示RAG而强制每题检索，也不能靠堆论文数证明检索有效。

后续扩充应记录真实获取/解析/索引数量与缺口，按论文版本去重，按任务权限检索。需要比较相同任务下的质量、tokens与时延，才可讨论RAG相对直接阅读的收益；本轮不新增该实验。

## 后续数据方案

见 [P1数据准备](improvement-plan.md)。先完成核心修复，再冻结采集范围、来源配额、模拟任务与预算；试点建议30–50篇但尚未执行/冻结。Codex模拟使用只产生模拟轨迹，不能成为“真实用户”或自己给出的金标准。

扩充时把语料导入、任务生成、标注核对和最终评分分开；确认集按论文/版本隔离，不只按题目随机拆分。报告任务完成/partial/失败及请求成本，来源故障不能静默剔除。样本较少时如实给出范围与不确定性，不追求一条好看的百分比。
